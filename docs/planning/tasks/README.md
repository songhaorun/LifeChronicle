# LifeChronicle 开发任务总览

任务已从 625 个原子检查项整理为 **89 个工作包**。每个工作包对应一块完整代码、
一个可运行组件或一个可端到端验收的功能，不再为每个字段、DDL 或测试夹具单独建文件。

## 三个方向

| 方向 | 阶段 | 工作包数 | 清单 |
| --- | --- | ---: | --- |
| 基础调研与协议约定 | 0–2 | 19 | [foundation-and-contracts.md](foundation-and-contracts.md) |
| 基本可用 | 3–8 | 40 | [minimum-usable-product.md](minimum-usable-product.md) |
| 扩展功能 | 9–12 | 30 | [extensions.md](extensions.md) |

完整阶段关系见[开发路线图](../development-roadmap.md)。

## 任务粒度

一个工作包应满足：

- 完成后能运行、演示或被另一个组件直接依赖；
- 内部可以包含代码、Schema、迁移、测试和文档；
- 验收结果是一个完整功能，而不是“新增一个字段”；
- 预计需要多个完全不同负责人时，应再拆成子任务；
- 只在工作包内部维护实现 checklist，不再扩展顶层任务数量。

## 状态

在表格第一列维护：

```text
[ ] 待开始
[-] 进行中
[?] 阻塞
[>] 待验收
[x] 已完成
```

每个已完成工作包必须在项目管理系统或 PR 中记录负责人、commit、测试命令、
报告路径和已知限制。

## 发布质量门

- 阶段 0–2 完成：底座冻结；
- 阶段 3–8 完成：基本可用 MVP；
- 阶段 9–12 完成：完整扩展平台。

阶段完成仍需运行对应 `make phase-<n>-gate`，但质量门不再作为额外开发任务。
